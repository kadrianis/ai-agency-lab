## automation

[Source publiée](https://github.com/kadrianis/business-automation/commit/08bb20fbc0475427bfc4ca3cec5a564896206229)

Usine GitHub : cycle de 21 jours, audit des publications et préparation du mail pédagogique après vérification

Apprentissage après publication : Problème résolu : distinguer une tâche programmée, une source réellement publiée et un mail effectivement envoyé. L'orchestrateur central décrit les sept parcours dans factory.config.json et calcule le cycle web/mobile de 21 jours. scripts/core.mjs calcule la date de Paris et contrôle la structure des reçus; scripts/verification.mjs relit le commit et la CI sur le même SHA avant d'accepter une preuve. Un test en échec, un run encore en cours ou un run portant sur un autre commit bloque le succès. scripts/audit.mjs inspecte les six dépôts, conserve les preuves dans reports/ et prépare un compte rendu en français seulement pour les publications vérifiées du jour. Le workflow GitHub Actions exécute les quatre tests puis l'audit, tous réussis sur cette livraison. Pour essayer : installer Node 22 ou supérieur, cloner le dépôt, exécuter npm test puis npm run audit; aucun paquet tiers n'est nécessaire. Le mail explique chaque sujet grâce au champ lesson du reçu et indique les parcours encore manquants. Limites : GitHub Actions ne génère pas les produits; la tâche Codex crée les incréments. Le connecteur Gmail doit encore être installé et connecté pour envoyer le message; un fichier email.json ne prouve pas l'envoi. Cette livraison est l'orchestrateur publié, pas les deux SaaS terminés ni une application hébergée.
